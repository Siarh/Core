DPScope — боевой измеритель и оптимизатор характеристик (Allods Sunshine 6.0)
=========================================================

УСТАНОВКА
1. Удалите старую папку аддона DPScope из Mods\Addons.
2. Распакуйте эту папку целиком в Mods\Addons (в игре: Mods\Addons\DPScope).
3. Перезапустите игру или перезагрузите аддоны.
В пакете нет файлов .luac: аддон грузит обычные .lua (папка Scripts). Тексты блока лежат в Locales (Opt*.txt), поэтому кириллица отображается корректно.

ГДЕ ВИДНО РЕЗУЛЬТАТ
Откройте окно деталей игрока (клик по вашему имени в списке). Внизу окна появился блок
"Оптимизация статов" с колонками Сейчас / Оптим. / Разн. Блок показывается только для вашего
персонажа. Режим ДД/Лекарь определяется автоматически (у кого больше суммарно урон или лечение).

ЧТО АДДОН ИЗМЕРЯЕТ САМ (за выбранный бой)
- Ср. решимость, %  : среднее значение Решимости, взвешенное по урону (лечению) каждого удара.
- Ср. HP цели, %    : среднее здоровье цели (союзника для лекаря) в момент ударов, взвешенное по урону.
                      Если игра не отдаёт здоровье цели, показывается "?" и берётся 50%.
- Ваш урон/лечение в секунду и входящий урон в секунду для защитного расчёта.
- Максимальное здоровье (если API не отдаёт, задайте командой /aou hp N).

ФАЙЛ НАСТРОЕК (альтернатива командам в чате)
Все параметры можно хранить в файле AoUMeterSettings.txt (в папке аддона), блок Settings.Opt в конце файла.
Откройте его блокнотом, впишите числа (комментарии рядом подсказывают, что куда), сохраните и перезагрузите
аддоны или игру. Порядок приоритета:
  1) значения по умолчанию -> 2) файл AoUMeterSettings.txt -> 3) значения, введённые командами /aou в чате.
Команды в чате сохраняются игрой сами и перекрывают файл только для тех параметров, которые вы меняли.
Правка файла действует после перезагрузки аддонов; команды в чате действуют сразу.

АВТО-ОПРЕДЕЛЕНИЕ ХАРАКТЕРИСТИК (build 10)
Аддон читает характеристики из игры сам: avatar.GetInnateStats() отдаёт по каждой характеристике
base (свободные очки, которые вы расставили), talents (вехи развития), equipment, buffs, enchants,
fairyBonus и effective (итог). Ничего вводить не нужно. Соответствие: Plain = Мастерство, Rage = Решимость,
Finisher = Беспощадность, CritChance = Удача, Vitality = Стойкость, Will = Воля, Lifesteal = Кровожадность.
  - закреплено (не перераспределяется): вехи (talents), бонус феи (fairyBonus), эффекты (buffs) и чары (enchants);
  - свободные очки F = сумма base по шести характеристикам (у вас 370): их можно вложить в ЛЮБЫЕ
    характеристики, и в атакующие, и в защитные;
  - бонусы экипировки (equipment) переключаются инсигниями внутри своей группы (атакующие / защитные);
  - Удача берётся целиком и очков не получает.
Деление свободных очков между атакой и защитой: максимизируется (множитель урона) x (время до смерти)^вес,
вес /aou bal 0-3 (1 = равноценны, 0 = только урон). Строка "Своб. очки А/З" в блоке показывает, как очки
расставлены сейчас и как рекомендуется (атака/защита). В первой строке блока написано "auto".

Что ещё нужно:
  /aou eq on|off   (build 14) по умолчанию on: бонусы экипировки можно переключать инсигниями внутри группы (атакующей
                   инсигнией между Мастерством, Решимостью, Беспощадностью; защитной между Стойкостью, Волей,
                   Кровожадностью), поэтому экипировку менять не нужно. off: двигаются только свободные очки.
  /aou thp N   среднее здоровье цели в %, если игра его не отдаёт (в блоке тогда "?"), по умолчанию 50
  /aou hp N    максимальное здоровье, если не определилось (нужно для защитной части)
  /aou hptest  (build 11) выделите цель (моба) и введите: покажет, отдаёт ли игра её здоровье, и счётчик удачных/неудачных
               чтений здоровья целей за бой (то же в /aou show)
  /aou probe   показывает, какие функции здоровья/уровня есть в игре (пришлите скриншот, если "?" остаётся)
Ручной ввод (/aou fix, free, base, atk, def) нужен только если авто-чтение не сработает.
  /aou auto on|off   включить или выключить авто-чтение

РЕЗИСТЫ, РУНЫ, РАНЫ (build 15)
Резисты (Броня, Стихии, Природа, Свет), блок, парирование, барьер и поглощение рунами не зависят от очков
характеристик, а множители урона (Мастерство, Решимость, Беспощадность, Удача) умножаются поверх них. Поэтому
на выбор атакующих характеристик они не влияют, а измеренные урон и лечение уже даны после них.
Что аддон делает с этими данными:
  - УВС: строка "Срез урона целью" показывает, какой процент удара срезали резисты цели, поглощение/руны и блок.
  - HPS и входящее лечение: строка "Потери лечения" показывает, сколько лечения забрали раны (поглощение лечения от
    Ярости и сопротивление лечению) и перелечивание.
  - Защита (режим Def): таблица "Входящий по типам": доля входящего урона по Броне / Стихиям / Природе / Свету,
    сколько срезал резист и сколько поглотили руны. Это справка для выбора экипировки: резисты очками не меняются.
  - Модель защиты: возврат Кровожадности умножается на (1 - доля ран). Доля ран (строка "Раны (погл. лечения)")
    измеряется по лечению, которое получает игрок. Если раны забирают много лечения, Кровожадность становится
    менее выгодной, и оптимум смещается в Стойкость.
Типы урона берутся из события урона (ENUM_SubElement_PHYSICAL/FIRE/COLD/LIGHTNING/POISON/DISEASE/ACID/HOLY/
SHADOW/ASTRAL).

ТЕСТЫ НА МАНЕКЕНЕ (build 16)
  /aou mark название   записывает в конфиг аддона одну строку про текущий бой: длительность, урон и урон в секунду,
                       число ударов и критов, средний пул Решимости, среднее здоровье цели, статы (итого и свободные
                       очки по каждой), максимальное здоровье, входящий урон в секунду.
  /aou rec list [N]    выводит последние N записей в чат вместе с названиями столбцов
Название пишите латиницей без пробелов, например base_d70 (манекен 70%), MmR_d100 (Мастерство +100, Решимость -100).
Записи лежат в файле конфигурации игры (ключи aou_rec_1, aou_rec_2, ... и aou_rec_count). Если не знаете, где он
на диске, найдите на диске файл, содержащий текст aou_rec_count (поиск по содержимому), и пришлите его мне.
Порядок: сбросьте бой кнопкой аддона, отбейте одинаковую ротацию 60 секунд, введите /aou mark название, повторите
3-5 раз для каждого набора характеристик.
Столбцы: n|label|mode|sec|dmg|dps|hits|crits|pool|poolc|thp|heal|hps|M|R|U|L|S|W|B|bM|bR|bU|bS|bW|bB|hp|inc

ОСТОРОЖНОСТЬ (build 17)
Осторожность: урон по вам ниже 40% здоровья умножается на (1 - s/1000), при s >= 350 это x0.65. База 100 у всех, плюс вехи.
Значение читается из игры (предположительно ENUM_InnateStats_Endurance: у вас база 100 + вехи 239 = 339) или задаётся
вручную: /aou caut N (0 = из игры). В защитной части блока появилась строка "Осторожность / здор. x": число и во сколько
раз она увеличивает эффективное здоровье (0.6 + 0.4 / (1 - c)). Время жизни считается в два этапа (выше и ниже 40%
здоровья): ниже 40% входящий урон меньше, а возврат Кровожадности остаётся, поэтому Кровожадность становится чуть выгоднее.
Осторожность целей (мобы, боссы, игроки в PvP) аддону вводить не нужно: измеренный урон уже сокращён ею. Среднее здоровье
цели теперь считается без смещения от самой Беспощадности (вес удара делится на (1 + m x (1 - HP цели))), поэтому оно
чуть выше, чем раньше.

УРОН ИЛИ ЛЕЧЕНИЕ
Блок анализирует то, что показано в окне аддона: режим УВС (урон) или ЛВС (лечение). Переключите режим
кнопкой в шапке окна, и рекомендации пересчитаются: для лечения берётся Решимость от исходящего лечения,
здоровье союзников и т.д. В режимах защиты (Def/IHps) используется роль (/aou role). Первая строка блока
показывает, что анализируется: "Анализ: урон" или "Анализ: лечение".

ЧТО ВВОДИТЕ ВЫ (вручную, если авто не работает) (один раз, сохраняется)
Игра не отдаёт аддонам разбивку характеристик на базу, вехи, экипировку и эффекты,
поэтому цифры вводятся командами в чат (как в калькуляторе):
  /aou atk fM fR fU L eM eR eU
      f = база + вехи развития (не перераспределяются), L = Удача всего,
      e = бонус экипировки + эффектов (свободные очки, перераспределяются)
      порядок: Мастерство, Решимость, Беспощадность
  /aou def fS fW fB eS eW eB
      то же для Стойкости, Воли, Кровожадности
  /aou mode pve|pvp      режим (в PvP Воля получает минимум очков для нужных секунд контроля)
  /aou tw 1-10           желаемые секунды контроля до иммунитета (PvP), по умолчанию 4
  /aou role dd|heal|auto роль, по умолчанию auto
  /aou flag on|off       on: перераспределять свободные очки; off: оптимум = текущее
  /aou hp N              максимальное здоровье, если не определилось само
  /aou show              показать сохранённые значения
  /aou                   справка

Пример: вехи дают Мастерству 120, Решимости 90; база 64/254/52; экипировка 151/464/321;
эффекты 0/50/0; Удача 160 всего.
  fM = 64+120 = 184, fR = 254+90 = 344, fU = 52, L = 160, eM = 151, eR = 464+50 = 514, eU = 321
  /aou atk 184 344 52 160 151 514 321

КАК СЧИТАЕТСЯ
Формулы из ваших данных: Мастерство x(1+s/1000), Решимость x(1+s/1000 x пул x 0.015),
Беспощадность x(1+m x (1-HP цели)), Удача: шанс крита f(s)/1000, крит x2 (Удача не получает
очков из других характеристик). Атака: максимизируется произведение множителей.
Защита: максимизируется время до смерти = здоровье / (входящий урон - возврат Кровожадности),
возврат не больше 95% входящего урона; Воля (PvP) получает минимум очков для /aou tw секунд.

ЭКСПОРТ ЖУРНАЛА И РАСШИРЕННЫЕ ЗАПИСИ (build 19)
------------------------------------------------
Новые команды:
  /aou rec export       экспорт последних 100 записей в чат (можно указать число: /aou rec export 250)
  /aou rec list [N]     просмотр последних записей

Экспорт в чат выдаёт строки-маркеры AOUCSV с нумерованными частями. Это сделано потому, что API аддонов
в этой версии не предоставляет подтверждённого безопасного способа записывать произвольные файлы на диск.
Как сохранить отдельный CSV-файл:
  1. В игре выполните /aou rec export [N].
  2. Скопируйте все строки, содержащие AOUCSV, из игрового чата в текстовый файл (например, export.txt).
  3. Откройте приложенный AoU_ChatLog_To_CSV.html в браузере.
  4. Выберите export.txt или вставьте текст в поле и нажмите «Собрать CSV».
  5. Нажмите «Скачать AoU_combat_log.csv».
Конвертер работает локально в браузере, интернет не требуется. Если пропущена часть строки, он сообщит об ошибке,
а не создаст тихо повреждённый файл. Старые записи build 16 также поддерживаются: отсутствующие новые поля будут пустыми.

В build 19 в записи боя дополнительно сохраняются:
  - количество успешных чтений здоровья цели и количество сэмплов пула Решимости отдельно для ДД и лечения;
  - средний пул Решимости и среднее здоровье цели отдельно для исходящего лечения;
  - исходящие срезы урона резистами, поглощением/рунами и блоком/парированием;
  - входящие резисты, поглощение/руны, блок/парирование;
  - распределение входящего урона по Броне, Стихиям, Природе и Свету;
  - поглощение лечения ранами и перелечивание.

Формула Мастерства дополнена веткой для отрицательного значения: 1/(1+|s|/1000). Для положительного значения
остаётся 1+s/1000. Остальные расчёты не заменяют измерения: формулы Решимости, резистов, ран и рунического
поглощения всё ещё требуют проверки на конкретной версии сервера.

ВАЖНО: модифицированный аддон и экспортёр не запускались в клиенте Allods Online в этой среде.
Проверена структура исходников и согласованность схемы экспорта; фактическую совместимость игрового API
можно подтвердить только после загрузки аддона в игре. Сохраните резервную копию старой папки перед заменой.


DPScope build 20 — переименование и команды
- Название аддона: DPScope. Папка установки: Mods\Addons\DPScope.
- Новая команда: /dpscope. Старая /aou сохранена для совместимости.
- Верхняя сводная группа показателей сохранена; дублирующая вкладка с теми же итогами не добавлялась.
- Общий УВС остаётся суммарным уроном за бой / длительность боя; УВС отдельного умения — отдельный показатель.
- Экспорт через чат AOUCSV оставлен как запасной вариант. Автоматическая запись произвольного CSV/TXT в папку Windows из Lua API аддона не подтверждена. Для настоящего сохранения файла без копирования чата нужен поддерживаемый файловый API клиента или внешний помощник; не заявляем, что это уже реализовано.

АНАЛИТИКА СОБЫТИЙ И ОПТИМИЗАЦИЯ ПО АКТИВНОСТЯМ (build 28)
-------------------------------------------------------
Коэффициент Решимости:
  /aou resolvecoef 0.015   буквальная формула, переданная пользователем: 1 + s/1000 x пул x 0.015
  /aou resolvecoef 0.0015  альтернативное значение из пояснения «+1.5% за каждые 10 пунктов».
По умолчанию выбран 0.015, потому что это значение стоит непосредственно в формуле. Эти варианты отличаются в 10 раз;
окончательно проверить масштаб можно только сравнением с пулом и фактическим уроном/лечением сервера.

В HPS-оптимизаторе появились отдельные строки лечения себя и союзников. Они используют среднее HP цели до лечения,
взвешенное величиной лечения, и наблюдаемый пул Решимости. Если HP для события недоступно, строка не может считаться
полной; символ ~ у HP означает оценку по post-событию или предыдущему снимку. Основная рекомендация строится на
распределении целей по диапазонам HP, а рекомендации self/ally пока используют отдельное среднее для каждого получателя.

Сырой журнал событий:
  /aou eventlog          состояние локального буфера и сохранённой истории
  /aou eventexport [N]   выгрузить последние N событий (по умолчанию 100, максимум 1000)
Экспорт отправляет в чат строки AOUCSV. Он не изменяет и не очищает старые /aou rec записи.
  1. Выполните несколько боёв в нужной активности и дождитесь остановки сбора боя.
  2. Выполните /aou eventlog и затем /aou eventexport 100.
  3. Скопируйте все строки AOUCSV в текстовый файл.
  4. Откройте AoU_ChatLog_To_CSV.html, вставьте файл, соберите и скачайте AoU_combat_log.csv.

История хранится отдельно от старых тестовых записей: до 1000 последних событий в GlobalConfigSection аддона.
В памяти текущего боя буфер ограничен 2000 событиями; при переполнении старые события текущего боя удаляются.
Поля, которые API не предоставляет, остаются пустыми. Для HP хранится отдельная пометка качества:
measured_pre, estimated_pre, post_only или unknown.

Офлайн-калькулятор и сравнение активностей:
  cd tools
  python aou_event_history_to_profile.py AoU_combat_log.csv --out aou_event_profile.json --budget 20
  python aou_formula_calculator.py aou_event_profile.json --out aou_report.json

Конвертер разделяет бои и режимы DPS/HPS. Общая рекомендация для нескольких боёв нормирует каждую активность
относительно её базового результата, чтобы самый большой по числам бой не подавлял остальные.
Для HPS формируются отдельные рекомендации self/ally, когда тип получателя и здоровье доступны.
Конвертер требует одинаковые M/R/U/L на всём импортируемом наборе. Для сравнения разных наборов экипировки сделайте
отдельные CSV/профили.

ОГРАНИЧЕНИЯ ТЕКУЩЕГО ИМПОРТА
- Callback игры сообщает наблюдаемую итоговую величину, а не сырой базовый урон/силу умения. Импортёр снимает известные
  множители M/R/U/крита; неизвестные коэффициенты цели (резист, блок, парирование, осторожность и т.п.) остаются
  внутри веса события. Поэтому это сопоставительный оптимизатор по записанным боям, а не точный реконструктор исходного удара.
- Пул Решимости сохраняется на каждом событии и фиксируется при альтернативном распределении статов. Его рост при
  изменении набора характеристик пока не пересчитывается: для этого нужно надёжно восстановить базовый удар и полный
  порядок всех множителей, включая защиту цели.
- Для HPS полезное лечение рассчитывается по HP до лечения и максимальному HP цели. События без максимального HP
  или с неизвестной фазой HP исключаются из консервативного импорта.
- Могущество, уровень, класс, полная сила магии/урона оружия и часть защитных полей не всегда доступны в callback.
  Они не участвуют в перераспределении M/R/U и не выдаются за известные параметры.
- Удача учитывается по ожидаемой вероятности крита в офлайн-расчёте; фактически зафиксированный крит используется для
  восстановления базового наблюдаемого события, если поле доступно.
- Входящие события также собираются в tank-профили. Когда API сообщает pre-hit HP, отдельное значение resist и
  rune absorb, а другие прямые компоненты блок/парирование/барьер/поглощение/маунт не положительны, конвертер
  восстанавливает оценку входящего удара и относительный рейтинг соответствующей группы: Броня, Стихии,
  Божественное или Природа. Рунное поглощение моделируется отдельно, не складываясь с общими API totals.
- Tank-оптимизация сравнивает Стойкость, Кровожадность, Осторожность и только те резист-группы, которые
  представлены пригодными событиями. Для HP используется записанное максимальное здоровье и относительный
  множитель Стойкости; если классный коэффициент Выносливости неизвестен, он не выдумывается.
- События с положительными блоком, парированием, барьером, общим поглощением или переводом урона в маунта
  временно исключаются из обратного восстановления резиста: эти прямые компоненты могут перекрываться и
  не должны суммироваться. Такие события остаются в обычной статистике /aou defstat.

Проверено автоматическими тестами/CI: синтаксис Lua, журнал событий, сохранение отдельной истории и AOUCSV-экспорт,
формульные unit-тесты, импорт CSV и создание профиля. Запуск в игровом клиенте Allods Sunshine 6.0 этим не заменяется.

ИИ-МОДУЛЬ DPSCOPE (build28 AI)
------------------------------
В игре:
  /aou ai on       включить локального AI-советника и строки анализа в блоке оптимизатора
  /aou ai off      выключить AI-советника
  /aou ai status   статус, тип движка и состояние
  /aou ai advice   повторить последний вывод советника
  /aou ai export   выгрузить до 1000 последних событий для последующего AI-разбора

Локальный советник работает без интернета. Он оценивает качество выборки (количество событий, покрытие HP и пула
Решимости), различает УВС/HPS и лечение себя/союзников, показывает осторожный следующий шаг для теста. Он не заменяет
формульный оптимизатор и не выдаёт эвристический вывод за измеренный факт. Состояние on/off сохраняется в отдельном
ключе aou_ai_enabled и не затрагивает старые /aou rec записи. По умолчанию советник включён.

ВНЕШНИЙ LLM-РАЗБОР НА ПК
-----------------------
Текущий desktop-помощник использует локальный Ollama API и не требует облачного API-ключа.
Подробная актуальная инструкция, проверка модели и команды запуска приведены в
DPScope\\tools\\README_ollama_ai.txt. Эта локальная инструкция заменяет ранний прототип
подключения OpenAI, описанный в предыдущих ревизиях build28.

ЛОКАЛЬНЫЙ ВНЕШНИЙ AI-ПОМОЩНИК (Ollama / Qwen 3.5)
--------------------------------------------------
Внешний desktop-помощник теперь по умолчанию использует локальный Ollama API:
  python tools/aou_ai_assistant.py --check
  python tools/aou_ai_assistant.py --profile aou_event_profile.json --report aou_report.json --out aou_ai_advice.md

По умолчанию помощник запускает qwen3.5:27b. Для явного выбора менее требовательной версии
используй --model qwen3.5:9b или переменную OLLAMA_MODEL. Адрес по умолчанию — http://localhost:11434;
его можно переопределить через --ollama-url или OLLAMA_HOST. API-ключ не нужен.
Подробная инструкция находится в tools/README_ollama_ai.txt внутри архива.

Этот локальный режим заменяет прежнюю инструкцию внешнего помощника через OpenAI API.
Запрос уходит только на локальный Ollama, если локальный сервер запущен. Первичная загрузка
модели через ollama pull может потребовать интернет. Сам игровой Lua-аддон по-прежнему
не вызывает Python и не обращается к Ollama напрямую: внешний AI-анализ запускается вручную.
Команды /aou ai on/off управляют только встроенным советником в интерфейсе игры, а не
отдельным процессом Python/Ollama.
