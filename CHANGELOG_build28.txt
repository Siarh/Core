DPScope build 28 - Allods Sunshine 6.0
======================================

Changes
- Analytics runs from the resolved DPScope combatant pipeline, once per event in the current fight.
- Personal analytics are filtered to the local player; party member events are not mixed into personal totals.
- Damage and healing phase reports use target HP snapshots where the game API exposes them.
- Healing report separates nominal, effective and overheal values. HP-delta estimates are labelled separately; unavailable values remain unknown.
- Defensive report exposes event components and API-reported totals separately to avoid double counting.
- Determination pool sampling records observed values and thresholds; missing values are not converted to zero.
- Existing DPScope commands and stored user test records are not cleared by this update.

Commands
/aou phase   - damage by target HP phase
/aou heal    - healing efficiency and overheal
/aou defstat - defensive event statistics
/aou stats   - observed determination pool statistics
/aou diff    - combined analytics summary

Limitations
- Mastery and Ruthlessness coefficients are not calibrated for Sunshine 6.0.
- HP phase attribution depends on the game's health API and event target IDs.
- Effective healing estimates require consecutive HP observations; reported overload is preferred when present.
- No claim of a validated stat optimum is made without controlled combat samples.


API integration update:
- Added per-object EVENT_OBJECT_HEALTH_CHANGED watches for observed targets and group units.
- Health deltas (healthDelta / healthPercentsDelta) are captured and correlated with personal damage/healing events when target, direction, and available amount agree.
- Exact HP transitions can be marked reported; percent-only transitions remain estimated.
- /aou stats now prints raw avatar.GetInnateStats() fields (sysName, effective, base, equipment, talents, enchants, buffs, fairyBonus, secondary) without assuming undocumented stat-name mappings.
- /aou phase reports health-change event coverage and unknown HP samples.

Caveats:
- Health-change event ordering relative to damage/healing callbacks must be validated in Sunshine 6.0 combat.
- Exact enemy HP and absorb values may be unavailable by design; percentage deltas are estimates for personal event attribution.
- Innate-stat enum names are exposed by the API, but their equivalence to Mastery / Determination / Ruthlessness must be validated against the Sunshine 6.0 client before using them as optimizer coefficients.
- No Lua runtime or in-game test has been run for this update.

Healing accounting clarification:
- Effective healing now subtracts the documented overload, wound resistance, rune wound resistance, and other absorbed-healing fields separately.
- When overload is unavailable but HP snapshots permit an estimate, wound/debuff losses are not misreported as overheal.

Additional defensive telemetry:
- Captures player additional-health pool increases/decreases from EVENT_OBJECT_HEALTH_CHANGED as shield-pool changes.
- These are deliberately reported as pool changes, not automatically equated with damage absorbed (expiry and other causes can also change the pool).
- Reconstructs pre-event health ratio using healthLimitDelta when maximum HP changes in the same event.
- Health event subscriptions are deduplicated and capped at 64 watched objects to limit event overhead; unmatched transitions are discarded instead of reused by later hits.


Offline formula engine update:
- Replaced the first prototype in tools/aou_formula_calculator.py with event-level DD / HEAL / TANK simulation and separate per-activity recommendations.
- Added Might, level multiplier, Mastery, Resolve, Ruthlessness, Luck/critical expectation, Bloodthirst, Fury healing absorption, Caution, Will, Endurance/Fortitude health, school resistances, block/parry and measured rune absorption.
- HPS optimisation now requires effective-heal evidence for every event unless allow_nominal_hps_optimization=true is explicitly selected.
- Resolve gain is simulated per event with the pool-dependent k and once-per-second decay; no guessed fixed divisor such as 2.4 is hard-coded. A per-event resolve_divisor_multiplier may be supplied.
- The Resolve multiplier coefficient ambiguity (0.0015 versus 0.015) is surfaced in report warnings and remains configurable.
- Added a three-activity profile template and 21 unit tests. Greedy allocation is explicitly labelled approximate, not exhaustive.
- This is an offline Python engine; raw event journaling/export from the live Lua addon is not yet connected.


Offline formula engine hardening:
- Reports damage/healing totals by target HP phase when pre-event HP is supplied, plus first-half/second-half activity rate comparisons.
- HPS recommendations now require data that can be recalculated under alternative stats (target missing HP or an effective-heal ratio); bare fixed effective-heal totals are reported but are not reused for build comparisons.
- Counterfactual optimisation uses expected critical probability from Luck instead of replaying historical crit/not-crit flags.
- Missing target HP is disclosed and DD/HPS allocation recommendations are refused when Ruthlessness cannot be modelled safely.
- Tank incoming mitigation is grouped by physical, elemental, divine and nature school, retaining separate resistance, block, parry and rune totals.
- Resolve pool can reset on explicit player_died / owner_died event markers.
- Formula engine has 27 unit tests covering the supplied formulas, data-coverage guards, phase/stability output and allocation budgets. Python tests were run in the development environment; the engine has not yet been connected to live Lua event export or validated with a new in-game fight.


Formula ordering refinement:
- Outgoing event calculation now applies resistance, block/parry and measured rune absorption before Ruthlessness, then target Caution, matching the supplied hit sequence.
- Added a regression test ensuring an absolute rune-absorbed amount is not amplified by Ruthlessness.
- Formula engine test suite now contains 28 tests. GitHub Actions completed successfully for the code and regression-test commits.


Saved-record analyzer correction:
- `tools/aou_analyze.py` now uses Resolve coefficient 0.0015 by default, matching the offline event calculator and the prose interpretation of +1.5% per 10 pool points.
- Added `--resolve-coefficient 0.015` to explicitly compare the literal-equation interpretation; the chosen coefficient is printed in the report.
- Added a regression test comparing both interpretations. GitHub Actions passed all 29 formula/analyzer tests.

- Explicitly documented that the legacy in-game Lua optimizer still uses 0.015 while the offline calculator/analyzer default to 0.0015; no silent change was made pending a controlled Sunshine 6.0 coefficient test.


Live diagnostics follow-up (based on the latest Sunshine 6.0 report):
- Enemy HP phase attribution now keeps the previous percentage-only HP snapshot and uses it as the next hit's pre-hit estimate. This addresses the failure mode where every hit was classified from the current post-hit percentage. Such samples remain explicitly estimated; they are not exact HP measurements.
- Automatic integer display of innate stats now truncates fractional API values (`floor`) instead of rounding half-up, matching the game's displayed integer convention (459/800/460 versus 460/800/461). Raw API values are still retained internally for calculations.
- Lua runtime validation is still pending in-game. The health-change callback produced only 3 events in the supplied report, so phase results must be rechecked after this change; the code does not claim exact phase reconstruction.

Whole-fight DD recommendation update:
- The in-game DD allocator now scores Mastery / Resolve / Ruthlessness by a weighted log-average across the exact target-HP checkpoints 100%, 75%, 50%, 25% and 0%. The weights approximate an even average over the four equal HP quarters, with shared boundaries split between adjacent quarters.
- This keeps Mastery and Resolve valuable from the opening hit while allowing Ruthlessness to contribute progressively as the target loses health; the low-HP execute phase is not allowed to dominate solely due to unusually large finishing hits.
- The addon now samples the observed Resolve pool separately in each target-HP quarter and uses those four measured averages in the DD curve objective; phases without samples fall back to the whole-fight average.
- This captures the observed Resolve build-up across a fight without inventing a future per-second Resolve trajectory. The target-HP buckets are based on the health value exposed at the combat event and remain subject to the existing HP attribution confidence.
- Controlled Resolve coefficient and pool-growth validation remain outstanding.
- No class-specific Fury/Neistoystvo mechanic was added.
